# EggPair: Palworld Breeding Calculator

A free, fast, mobile-first Palworld breeding site: calculator, parent finder, route planner, My Pals tracker and a page for every Pal. It is a plain static website: no server, no database, no paid services, and no npm dependencies.

- **Data:** [PalCalc](https://github.com/tylercamp/palcalc) by Tyler Camp (MIT licence), exported from the Palworld 1.0 game files. See `data/meta.json` and the site's `/data-sources/` page.
- **Cost:** $0. Hosting on Cloudflare Pages' free plan with a free `*.pages.dev` address.

## Folder map

| Path | What it is |
|---|---|
| `data/` | Pal list, breeding table, version info and the PalCalc licence. Generated by the import script; don't edit by hand. |
| `site.config.mjs` | Site name, address, contact email, analytics, ads and affiliate settings. |
| `src/build.mjs` | Builds every page into `dist/`. |
| `src/content.mjs` | Text of the guide, About, Privacy, Contact, Disclaimer and Data sources pages. |
| `src/lib/breeding.mjs` | Breeding logic shared by the browser and the tests. |
| `src/assets/` | CSS, browser JavaScript, favicon and Cloudflare `_headers`. |
| `tests/` | Data, logic and SEO checks (`npm test`). |
| `scripts/` | Data import, local preview server, browser smoke test. |

## Everyday commands

You need [Node.js](https://nodejs.org) 20 or newer. Nothing else to install.

```bash
npm run build    # make the site in dist/
npm test         # run all checks (build first)
npm run check    # build + test in one go
npm run serve    # preview at http://localhost:4321
npm run smoke    # phone-size browser test (needs Playwright: npm i -D playwright && npx playwright install chromium)
```

## Deploy for free on Cloudflare Pages

1. Make a free account at <https://dash.cloudflare.com/sign-up>.
2. Go to **Workers & Pages → Create → Pages → Connect to Git**, allow access to this GitHub repository and pick it.
3. Build settings:
   - Framework preset: **None**
   - Build command: `npm run check`
   - Build output directory: `dist`
   - Environment variable: `NODE_VERSION` = `22`
4. Choose the project name. Your address becomes `https://<project-name>.pages.dev`.
5. Under **Settings → Variables and Secrets**, add `SITE_URL` = `https://<project-name>.pages.dev` (no slash at the end), then **redeploy**. This makes canonical links and the sitemap use the right address.

Every push to `main` now redeploys automatically. If a test fails, Cloudflare stops and the old version stays live.

### Alternative: Cloudflare Workers (static assets)

If the Pages GitHub connection doesn't work, the same site can be served by Workers using `wrangler.jsonc` (static files only, no Worker code, so requests aren't billed):

1. **Workers & Pages → Create application → Connect GitHub**, pick this repository.
2. Build command: `npm run check`. Deploy command: `npx wrangler deploy`. Add the variable `NODE_VERSION` = `22`.
3. The site appears at `https://palworld-breeding.<your-subdomain>.workers.dev`. Set `SITE_URL` to that address and redeploy.

### Optional settings (Cloudflare environment variables)

| Variable | What it does |
|---|---|
| `SITE_URL` | Your live address. Required for correct SEO tags. |
| `CONTACT_EMAIL` | Shown on the Contact page. Ad networks expect a way to contact you. |
| `CF_ANALYTICS_TOKEN` | Free Cloudflare Web Analytics (no cookies). Get it under **Analytics & Logs → Web Analytics → Add a site**. |
| `GOOGLE_SITE_VERIFICATION` | Code for Google Search Console's "HTML tag" method. |
| `ADS_ENABLED`, `ADSENSE_CLIENT`, `AD_SLOT_BELOW_TOOL`, `AD_SLOT_IN_CONTENT` | Only after an ad network approves you. See below. |

## Google Search Console

1. Open <https://search.google.com/search-console> and add a **URL prefix** property with your full address (for example `https://palworld-breeding.pages.dev/`).
2. Choose **HTML tag**, copy only the `content="…"` value, set it as `GOOGLE_SITE_VERIFICATION` in Cloudflare, redeploy, then press **Verify**.
3. Go to **Sitemaps** and submit `sitemap.xml`.
4. Check **Pages** after a few days to see what Google indexed. New sites often take weeks; nothing here guarantees indexing or rankings.

## Ads and affiliate links

Ads are off. No ad code loads until you switch it on.

- **Google AdSense** reviews the site before showing ads. It looks for original, useful content, clear navigation, and the About, Privacy and Contact pages (already included; set `CONTACT_EMAIL`). AdSense generally needs a site you own at the domain level, so a free `pages.dev` address may not be accepted; a custom domain (about $10–15 a year) may be needed. Approval is never guaranteed.
- When approved: set `ADSENSE_CLIENT` (`ca-pub-…`), create two display ad units and put their IDs in `AD_SLOT_BELOW_TOOL` and `AD_SLOT_IN_CONTENT`, set `ADS_ENABLED=true`, redeploy. The build also writes `ads.txt` and the privacy page switches to its ad wording automatically.
- Higher-paying networks (Mediavine, Raptive, etc.) require much more traffic; check their current requirements.
- **Affiliates:** only add links from programmes you have actually joined (for example a game-server host's affiliate programme). Add them to `affiliates` in `site.config.mjs`; the Disclaimer and Privacy pages already disclose affiliate links.

## Updating the data after a game update

```bash
git clone --depth 1 https://github.com/tylercamp/palcalc /tmp/palcalc   # after PalCalc has updated for the new patch
npm run import-data -- /tmp/palcalc
npm run check
```

The import compares every one of PalCalc's breeding rows with the converted table and refuses to write anything if one disagrees. The tests then recompute every regular result from breeding power. Review `data/meta.json`, update `gameVersion` in `scripts/import-palcalc.mjs` if the game version changed, then commit and push.
